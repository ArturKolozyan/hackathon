# Product — Invoice Keeper (AEZA)

[AGENTS.md](../AGENTS.md) · [infra](infra.md) · [design](design.md) · [pitch](pitch.md) · [qa](qa.md)

**Статус:** одна установка — одна организация. Согласовано как on-prem кейса, 2026-10-24.

**Живой адрес:** https://rekeeper.ru. Тот же `docker-compose.yml`, отличия только в `.env`.

## Идея

**Инбокс обязательств** — очередь действий, не журнал:

- сверху то, что нужно сделать: просрочено → скоро → остальное;
- пункт = период («Сервер · ноябрь · $40 · до 12.11»), не шаблон;
- закрыл — ушёл из инбокса, история жива;
- **Telegram = второй экран** того же инбокса (карточка + «Оплачено»).

Фраза: «Напомнил в Telegram — закрыл в один клик — история не потерялась.»

Не делаем: бухгалтерию, банк, курсы, OCR. «Оплачено» = подтверждение человеком. Ассистент не советует: факты из базы, запись только после «Подтвердить». См. [assistant.md](assistant.md).

## Кто

Одна компания. Отделы — строки таблицы `teams`, в интерфейсе «отдел». Человек может быть в нескольких отделах, в шапке переключатель.

| Роль | Что может |
|------|-----------|
| Владелец | один, из `OWNER_EMAIL` / `OWNER_PASSWORD` (если пусто — `ADMIN_*`). Отделы, админы, все платежи. Учётку нельзя сменить, удалить, заблокировать или понизить через панель и `PATCH`/`DELETE /users` |
| Админ отдела | в своём отделе то же, что владелец, кроме чужих отделов и учётки владельца. Людей создаёт только в своём отделе |
| Пользователь | платежи своих отделов, оплата, отмена, правка фактической даты. Те же границы в API |

Публичной регистрации, самосоздания организации, входа по приглашению и передачи владения нет. Вход — `POST /auth/login`. Сброс пароля — код на почту. Новый человек: временный пароль, на первом входе смена, затем необязательная привязка Telegram.

Владелец создаётся при старте API всегда, не только при `SEED_DEMO`. Пароль уже существующего человека с той же почтой не перезаписывается.

## Логика (из брифа)

1. Шаблон ≠ период (у периода свой статус). Периодичность — месяц, день месяца берётся из «даты ближайшей оплаты».
2. Просрочка не стопает следующий месяц.
3. Оплата в день срока — вовремя; правка фактической даты пересчитывает просрочку и не двигает срок.
4. TG: напоминание с T-3 по день срока и отдельно «просрочено» со следующего дня; оба один раз. Удаление шаблона стопает напоминания, история остаётся. Платёж, созданный уже внутри окна T-3, ставится в очередь сразу.
5. Единый TZ; нет числа в месяце → последний день.
6. RUB/USD/EUR, итоги раздельно, без курса.

## Каналы

Почта по умолчанию включена. Личный Telegram — после привязки. Выбор: «только мои платежи» (`notify_scope=mine`, по умолчанию) или «все платежи отдела», и просрочки в личку да/нет. Выключенный тумблер Telegram молчит и для ответственного. Чат отдела просрочку получает всё равно.

По умолчанию ответственный получает личное напоминание, чат отдела — общее. Дедуп: период, событие, канал, получатель.

«Оплачено» в чате пишет оплату на нажавшего, если он привязан и в отделе. Иначе бот присылает ссылку привязки и оплату не ставит.

Без `TELEGRAM_BOT_TOKEN` и без SMTP остальное работает. Канал в интерфейсе показан как не настроенный.

## Процессы

Код — модули одного репозитория. Контейнеры: `web`, `api`, `worker`, `bot`, `assistant`, `db`, `caddy`. Рядом служебный `backup`.

- `api` не ходит в Telegram и не зависит от `bot` и `assistant`.
- `worker` держит горизонт периодов, письма и webhook. Карточки Telegram кладёт в outbox.
- `bot` забирает outbox, long polling, «Оплачено», привязки. Имя для t.me — из getMe в базе или `TELEGRAM_BOT_USERNAME`.
- `assistant` — отдельный процесс. Стартует, только если в `.env` есть `COMPOSE_PROFILES=assistant` (рядом с ключом GigaChat). Голос — если задан ещё и SpeechKit. ffmpeg только в его образе.

`GET /api/v1/features` говорит панели, включён ли ассистент и отвечает ли процесс. Упавший ассистент не останавливает кейс: в чате и в боте «Ассистент временно недоступен».

Запись ассистента — только после «Подтвердить» и теми же функциями, что обычные эндпоинты. Сессия пользователя та же.

## Демо

`SEED_DEMO=true` и в базе ещё нет отделов: владелец, админ `maria@invoice.local`, пользователь `ivan@invoice.local`. Отделы «Бухгалтерия» (аренда RUB, сервер USD, подписка EUR) и «Инфраструктура». Пароли в [README](../README.md).

Сценарий жюри: вход владельца → платёж → напоминание → вход пользователя и «Оплачено» → просрочка → правка даты → следующий период.
