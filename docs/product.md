## Идея

**Инбокс обязательств команды** — не плоский журнал всех платежей, а очередь действий:

- сверху то, что нужно сделать: просрочено → скоро → остальное;
- пункт = период («Сервер · ноябрь · $40 · до 12.11»), не абстрактный шаблон;
- закрыл — ушёл из инбокса, история жива;
- **Telegram = второй экран того же инбокса** (карточка + кнопка «Оплачено»).

Фраза: «Напомнил в Telegram — закрыл в один клик — история не потерялась.»

Не делаем: бухгалтерию, банк, курсы, OCR, AI-советник. «Оплачено» = подтверждение человеком.

## Боль и кто

- **Админ** — что платим (шаблоны, юзеры). Боль: список в чатах и головах.
- **Пользователь** — что сделать сейчас. Боль: неясно что срочно, забывают чужой платёж.
- Заказчик кейса AEZA / любая IT-команда с регуляркой в RUB/USD/EUR.

## Логика (из брифа)

1. Шаблон ≠ период (у периода свой статус).
2. Просрочка не стопает следующий месяц.
3. Оплата в день срока — вовремя; правка факт. даты пересчитывает просрочку.
4. TG ≥3 дня / сразу если поздно; без дублей; удаление шаблона стопает напоминания, история остаётся.
5. Единый TZ; нет числа в месяце → последний день.

## Telegram

Второй экран того же инбокса. Процесс `worker`, не API. Транспорт — long polling `getUpdates`, не webhook: публичный HTTPS боту не нужен. `bot_username` worker берёт из `getMe` и кладёт в базу: deep link собирает API, ему сеть до Bot API не нужна.

- Напоминание, когда до срока ≤ `SOON_DAYS` (3) или период уже просрочен. «Остальное» молчит, пока не войдёт в окно. Появился уже в окне или просроченным — сразу.
- Чат команды подключает админ: Настройки → «Подключить чат команды» → `https://t.me/<bot>?startgroup=<токен>`. Бот в группе по `/start <токен>` сохраняет `chat_id` и отвечает «Подключено к rekeeper». В вебе — название, статус, «Отправить тестовое», «Отключить». Токен одноразовый, 15 минут. Другой чат заменяет прежний. `my_chat_member` left/kicked → статус «отключено». Миграция группы в супергруппу (`migrate_to_chat_id`) переписывает `chat_id` карточек.
- `TELEGRAM_CHAT_ID` — только запасной чат, если в базе ещё нет привязки. Явное «Отключить» запасной чат глушит.
- Личный Telegram: любой человек в Настройках → «Привязать Telegram» → `https://t.me/<bot>?start=<токен>`. В личке бот связывает telegram user id и отвечает «Привет, <имя>!…». Один Telegram — один пользователь rekeeper. `/start` без токена — короткая подсказка. В профиле видны @username и «Отвязать». Личные напоминания выключаются тумблером.
- Если у шаблона есть ответственный и он привязал Telegram (тумблер включён) — то же напоминание дублируется ему в личку. Нет привязки или тумблер выключен — только чат команды. Дедуп: канал + получатель (`team` или `user:<id>`), без второй отправки того же адресата.
- Текст: название, сумма, валюта, срок, статус. Inline-кнопка «Оплачено».
- Кнопка в чате команды и в личке ставит `paid_at` = сейчас в `TIMEZONE`, `paid_by` = пользователь rekeeper, чей Telegram нажал. Журнал `occurrence.paid`, в meta `source=telegram`. Заметку кнопка не меняет. Непривязанный клик ничего не пишет: алерт «Сначала привяжи Telegram в профиле rekeeper» (в алерте Telegram нет кликабельной ссылки). Уже оплачено — алерт «Уже оплачено — <имя>».
- После оплаты карточка правится: строка «✅ Оплачено — <имя>, <дата>», кнопка снимается. Оплата или возврат в инбокс с веба правят то же сообщение (кнопка снимается или возвращается). Это не второе напоминание.
- Пустой токен — worker не падает, горизонт периодов жив. Демо-сид поднимается без бота.
- С VPS Aeza к Bot API только IPv6 (`TELEGRAM_FORCE_IPV6`). Тестовое сообщение ставит API в очередь, отправляет worker.

## Скоуп первой цельной версии

**Must:** авторизация · инбокс/список · CRUD шаблонов и юзеров у админа · периоды · просрочка · TG · итоги по валютам · API `/api/v1/*` · OpenAPI+Swagger · README · `.env.example` · тестовые данные · persistence.

**Should в этой же версии:** кнопка «Оплачено» в TG (worker, этот кусок) · календарь · чек/ссылка · UX-фильтры инбокса.

## Should / Stars

Кнопка Telegram живёт в `deliver()` того же worker, что почта и webhook. Дедуп — по каналу и получателю. Остальные звёзды:

| Звезда | Контракт |
|--------|----------|
| Чек или ссылка | На периоде `receipt_url` (только https) и `receipt_note`. PATCH отдельно или вместе с оплатой. В карточке инбокса и в истории. Файлы не храним. |
| Календарь | `GET /api/v1/payments/calendar?year=&month=` — периоды по `due_date`. Экран месяца, клик открывает тот же период. Цвета статусов как в инбоксе. |
| Итоги на дату | `GET /api/v1/payments/summary?as_of=YYYY-MM-DD`. Без параметра поведение прежнее. На дату оплата позже этого дня ещё не засчитана, просрочка считается тем же правилом, что сегодня. Дальше горизонта от этой даты периоды не показываем. |
| Бюджет | `budgets`: month `2026-10` или year `2026`, валюта, сумма. CRUD только админ, отчёт всем. Факт — оплаченные периоды этого месяца/года, ожидается — ещё открытые. Не кассовая дата и не курс. |
| Логи | login/logout, шаблоны, люди, оплаты, бюджет, чек. Страница «Логи» только админ. В meta нет паролей, токенов и секретов. |
| Email | Тот же сигнал, что напоминание. `should_remind` — одно место с порогом SOON_DAYS. `EMAIL_ENABLED=false` или пустой SMTP — тишина. В конце письма строка `APP_PUBLIC_URL` (по умолчанию https://rekeeper.ru). |
| Webhook | `occurrence.reminder`, `occurrence.paid`, `occurrence.unpaid`. До 3 попыток с backoff. Пустой URL — тишина. Подпись `X-Rekeeper-Signature`, если задан секрет. |
| Другие каналы | Webhook и почта. Slack не делаем. |

Дедуп отправки — по каналу и получателю, не один флаг на период: письмо сегодня не запрещает Telegram, общий чат не запрещает личку ответственного.

## Демо жюри

Админ → платёж → TG → (кнопка) оплата → просрочка → правка даты → следующий период.
