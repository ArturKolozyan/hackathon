# Product — Invoice Keeper (AEZA)

[AGENTS.md](../AGENTS.md) · [design](design.md) · [pitch](pitch.md) · [qa](qa.md)

## Кейс

Middle, приз 100 000 ₽. Командный календарь регулярных расходов: админ заводит платежи, система напоминает в Telegram за 3 дня, команда отмечает оплату. Ответы: что и когда платить · что оплачено · что просрочено. Валюты RUB / USD / EUR отдельно, без курсов.

**Роли:** админ из `.env` (платежи + юзеры); пользователь (список + статус + дата оплаты). Права те же в UI и API. Админов через панель не меняют.

## Скоуп

**Must:** авторизация · список с суммой/валютой/сроком/статусом/датой/просрочкой · CRUD платежей и юзеров у админа · периоды со своей историей · просрочка со следующего дня (оплата в день срока — вовремя) · TG ≥3 дня без дублей (ближе 3 дней → сразу; оплачен/удалён/уже напомнили → тишина) · итоги по валютам · API `/api/v1/*` · OpenAPI + Swagger · README + `.env.example` + тестовые данные · persistence.

**Should (порядок):** 1) кнопка «Оплачено» в TG · 2) календарь · 3) чек/ссылка к периоду · 4) UX-фильтры (скоро / просрочено / валюта).

**Later:** бюджет месяц/год · email · webhook · логи.

## Логика

- **Регулярный платёж** — шаблон (название, сумма, валюта, ближайшая дата, период; must = ежемесячно). DELETE = стоп напоминаний, история остаётся. TZ из настроек/`.env`; нет числа в месяце → последний день.
- **Период (occurrence)** — свой срок и статус; новый не затирает старые; просрочка не стопает следующие.
- **Статусы:** не оплачено ↔ оплачено (+ факт. дата; отмена чистит дату). Правка даты пересчитывает просрочку, срок не меняется.
- **API:** auth login/me/logout · recurring-payments · payment-occurrences (+ PATCH) · payments/summary · users · `/docs`.

## Сценарии / демо жюри

1. Админ входит → 2. добавляет платёж → 3. напоминание в TG → 4. юзер отмечает оплату → 5. просроченный → 6. правка факт. даты → 7. следующий период отдельно. Вживую. Should #1 — wow между 3 и 4.
