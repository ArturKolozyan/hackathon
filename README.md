# Invoice Keeper

Инбокс регулярных обязательств команды: сверху просрочено, потом скоро, потом остальное. Период — это карточка («Сервер · ноябрь · $40 · до 12.11»), шаблон — только правило. «Оплачено» подтверждает человек, не банк.

Telegram — второй экран того же инбокса. `worker` зовёт общий `dispatch_due_reminders`: почта, webhook и `deliver()`. Кнопка «Оплачено» приходит long polling-ом в том же процессе.

## Сервер

https://rekeeper.ru

`www.rekeeper.ru` отвечает 301 сюда. TLS выпускает Caddy. Push в `main` деплоит. DNS, куки, порты и Telegram по IPv6: [docs/infra.md](docs/infra.md).

## Запуск

```bash
cp .env.example .env
docker compose up --build db api worker web
```

Windows:

```powershell
copy .env.example .env
docker compose up --build db api worker web
```

Без `caddy` в списке сервисов: полный `up` на ноутбуке начнёт выпуск сертификата `rekeeper.ru` и может на час занять лимит неудачных попыток Let's Encrypt перед первым выпуском на VPS.

- Приложение: http://localhost:8080
- Swagger: http://localhost:8080/api/v1/docs
- API напрямую: http://localhost:8000/api/v1/docs
- OpenAPI в репозитории: [openapi/openapi.json](openapi/openapi.json)

Порты `8080`, `8000` и `5432` на хосте слушаются только на `127.0.0.1`. Наружу приложение выходит через Caddy: `80` и `443` (и `443/udp` для HTTP/3). Для разработки хватает http://localhost:8080. Если на VPS порты 80/443 заняты чужим процессом, сайт снаружи не встанет — см. [docs/infra.md](docs/infra.md). Локально, если они заняты и Caddy всё же нужен, в `.env` задают `CADDY_HTTP_PORT` и `CADDY_HTTPS_PORT`. На VPS эти переменные не задавать.

Данные Postgres лежат в томе `pgdata` и переживают `docker compose restart`. Демо создаётся один раз, только если база пустая и `SEED_DEMO=true`. Рестарт API пароли не перезаписывает. Уже заполненная база миграцией собирается в одну команду «Команда»: первый админ становится владельцем, остальные — участниками.

nginx в `web` резолвит имя `api` на каждый запрос. `docker compose up -d --force-recreate api` не оставляет `/api/*` в 502. Подробнее в [docs/infra.md](docs/infra.md).

### Демо-вход

Пароли из `.env`, они же на экране входа. Общий пароль Ивана, Марии и Олега — `DEMO_USER_PASSWORD`.

| Кто | Почта | Пароль | Где какая роль |
|-----|--------|--------|----------------|
| Админ | `admin@invoice.local` | `change-me` | владелец «Студия Север», участник AEZA Ops |
| Иван | `ivan@invoice.local` | `change-me-user` | участник Студии, владелец AEZA Ops, участник «Маркетинг» |
| Мария | `maria@invoice.local` | тот же | участник Студии, админ AEZA, владелец «Маркетинг» |
| Олег | `oleg@invoice.local` | тот же | админ Студии, участник AEZA, админ «Маркетинг» |

У админа текущая команда — Студия Север: аренда (RUB), сервер (USD), подписка (EUR). Есть просрочка, ближайший срок, будущее и история, одна оплата с опозданием. У Ивана в статистике видны все три команды.

Участник видит очередь и может закрыть период. Шаблоны, состав и журнал — владелец и админ этой команды. Права проверяет API.

## Что в compose

| Сервис | Роль |
|--------|------|
| `db` | PostgreSQL 16, том `pgdata` |
| `backup` | Раз в сутки в 00:00 МСК `pg_dump` в `./backups`, 7 последних. На VPS это `/opt/invoice-keeper/backups`. Восстановление: [docs/infra.md](docs/infra.md) |
| `api` | FastAPI, миграции Alembic, сид, `/api/v1` |
| `worker` | Горизонт периодов и Telegram: long polling, напоминания, кнопка «Оплачено». На VPS — сеть хоста |
| `web` | Собранный React за nginx, `/api` проксируется на `api`. На хосте только `127.0.0.1:8080` |
| `caddy` | HTTPS для `rekeeper.ru`, 301 с `www` на https://rekeeper.ru, gzip/zstd |

Локально без Docker: поднять Postgres, `pip install -r backend/requirements.txt`, из `backend/` выполнить `alembic upgrade head` и `python -m app.entrypoint serve`, воркер — `python -m app.entrypoint worker`, фронт — `npm install && npm run dev` в `frontend/` (прокси `/api` на порт 8000).

Тесты:

```bash
docker compose exec api python -m pytest -q
```

## Допущения этого куска

Бриф AEZA с точными полями в репозиторий не положен, поэтому контракт зафиксирован в OpenAPI.

- «Скоро» = срок через `SOON_DAYS` дней или раньше (по умолчанию 3, как порог напоминания в [docs/product.md](docs/product.md)). В день срока это ещё не просрочка: оплата в этот календарный день — вовремя.
- Дата считается в `TIMEZONE` (Москва). Если в месяце нет такого числа — последний день.
- Просрочка не отменяет следующий месяц: воркер и чтение инбокса достраивают периоды на `HORIZON_MONTHS` вперёд.
- Неоплаченный период подхватывает сумму, валюту, день и название шаблона. Оплаченный — снимок.
- Удаление шаблона в API — архив: новые периоды не рождаются, старые строки остаются.
- Закрыть период и поправить фактическую дату может любой участник команды. Дата оплаты не может быть в будущем. Шаблоны, состав и журнал — владелец и админ. Роль живёт в членстве: один человек может быть в нескольких командах.
- Итоги (`GET /api/v1/payments/summary`) — суммы по валютам, без курса. `?as_of=YYYY-MM-DD` считает их на конец этого дня в `TIMEZONE`: оплата позже даты ещё открыта, просрочка по тому же правилу. Без параметра — как сейчас.
- Календарь (`GET /api/v1/payments/calendar?year=&month=`) — периоды месяца по дате срока. В панели клик открывает карточку.
- Чек периода: `receipt_url` (https) и `receipt_note`. Меняются через PATCH, в том числе отдельно от оплаты.
- Бюджет текущей команды: владелец и админ задают план на месяц (`2026-10`) или год (`2026`) по каждой валюте. Факт — сумма закрытых периодов, «ожидается» — ещё открытые. Отчёт видят все в команде.
- Журнал (`GET /api/v1/audit-logs`) — владелец и админ текущей команды. Вход, выход, шаблоны, состав, оплаты, бюджет, чек. Пароли и токены в журнал не пишутся.
- Статистика (`GET /api/v1/stats`) — по всем командам, где состоит человек, любая роль. Клик по команде в вебе переключает инбокс.
- Коды и приглашения: `SMTP_HOST` и соседние `SMTP_*`, без `SMTP_TO` и без `EMAIL_ENABLED`. Пустой хост — код в логе API. Напоминания по-прежнему требуют `EMAIL_ENABLED` и `SMTP_TO`. Порт 465 не использовать: с VPS работает 2525 и `SMTP_TLS=true`.
- Напоминание решает один сервис `should_remind`: не оплачен, шаблон не в архиве, до срока ≤ `SOON_DAYS` (просрочка тоже). Каналы это правило не копируют.
- Почта: `EMAIL_ENABLED=true` и заполненные `SMTP_HOST`, `SMTP_FROM`, `SMTP_TO`. Иначе воркер молча пропускает письмо. В конце письма строка `APP_PUBLIC_URL` (в примере `https://rekeeper.ru`). Пустое или без `http://`/`https://` — строка не добавляется.
- Webhook: `WEBHOOK_ENABLED=true` и `WEBHOOK_URL`. События `occurrence.reminder`, `occurrence.paid`, `occurrence.unpaid`. До `WEBHOOK_ATTEMPTS` попыток. Секрет даёт заголовок `X-Rekeeper-Signature: sha256=<hmac тела>`.
- Успешная отправка помнится отдельно по каналу (`notification_deliveries`). Письмо не блокирует Telegram. Пустой токен — канал пропускается и не помечается отправленным.
- Сессия: opaque-токен в httpOnly-куке и в теле логина (`Authorization: Bearer`). Logout отзывает её на сервере.

## Telegram

Бот живёт только в `worker`. Транспорт — long polling (`getUpdates`), webhook не используем. Секреты только в `.env`, в git их нет.

### Как подключить

1. В [@BotFather](https://t.me/BotFather) команда `/newbot`. Имя — `rekeeper`, username любой свободный. Privacy mode оставьте **включённым**: боту нужны команды, callback и статус участника, не вся переписка группы.
2. Токен впишите в `TELEGRAM_BOT_TOKEN`. `TELEGRAM_CHAT_ID` можно не заполнять.
3. Перезапустите `worker`. Он сам вызовет `getMe` и запомнит username бота.
4. Админ в вебе: **Настройки → Подключить чат команды**. Ссылка `t.me/<bot>?startgroup=…` действует 15 минут. Добавьте бота в группу — в чате появится «Подключено к rekeeper».
5. Каждый человек: **Настройки → Привязать Telegram**. Ссылка открывается в личке. После этого кнопка «Оплачено» пишется на него, а если он ответственный — туда же приходит личное напоминание. Тумблер «Личные напоминания» это выключает.

Группа, где писать могут только админы, должна дать боту право писать. Иначе тестовое сообщение не дойдёт.

| Переменная | Смысл |
|------------|--------|
| `TELEGRAM_BOT_TOKEN` | токен BotFather. Пусто — worker молча держит горизонт периодов и пишет в лог, что Telegram пропущен |
| `TELEGRAM_CHAT_ID` | запасной числовой id, только если команда в установке одна и чат ещё не привязан. Несколько команд — переменная не используется. Явное «Отключить» глушит запасной чат |
| `TELEGRAM_FORCE_IPV6` | `true` по умолчанию. Сокет сажается на `::`, IPv4 даже не коннектится (на московском VPS он таймаутится) |

После правки `.env` перезапустите `worker`. Клиент не берёт `HTTP_PROXY` из окружения.

Порог один: `should_remind` (не оплачен, шаблон не в архиве, до срока ≤ `SOON_DAYS`, просрочка тоже). `deliver()` этот порог не считает. Успех помнится по каналу и получателю: общий чат (`team`) и личка ответственного (`user:<id>`) друг друга не блокируют. `NotImplementedError` — пропуск, сетевая ошибка — повтор на следующем тике. Первый запуск с уже подключённым чатом и демо-сидом пришлёт по одному сообщению на каждый открытый период в этом окне.

Кнопка «Оплачено» ставит `paid_at` = сейчас в `TIMEZONE`. `paid_by` — **пользователь rekeeper, чей Telegram нажал**. Непривязанный клик оплату не ставит. Заметка периода не меняется. Повтор показывает, кто уже закрыл. В карточке строка «✅ Оплачено — имя, дата», кнопка снимается.

Оплата и возврат в инбокс с веба правят то же сообщение (и личку, если она была). Это синхронизация, не второе напоминание. На карточке периода после отправки есть пометка «в Telegram».

Тестовое сообщение из веба отправляет worker: контейнер API на VPS часто без IPv6 до Bot API.

На VPS Aeza у контейнера в bridge нет маршрута IPv6, хотя с хоста `api.telegram.org` по IPv6 открывается. Деплой поднимает worker в сети хоста: [compose.telegram-host.yml](compose.telegram-host.yml). Postgres при этом опубликован на `127.0.0.1`, и worker (тот же loopback, что у VPS) ходит туда, а не на имя `db`. `api`, `web` и `caddy` остаются в bridge. Локально на Docker Desktop для панели второй файл не нужен.

## Ассистент

Раздел «Ассистент» в вебе и личка бота. Короткие команды читают базу без модели. Создание, правка, архив и «оплачено» сначала карточка с кнопками «Подтвердить» / «Изменить». Голос: микрофон в вебе (webm → ffmpeg → SpeechKit) и голосовые Telegram (уже ogg). Фразы и ожидаемое поведение: [docs/assistant.md](docs/assistant.md).

`GIGACHAT_AUTH_KEY`, `GIGACHAT_SCOPE`, `YANDEX_SPEECHKIT_API_KEY`, `YANDEX_FOLDER_ID` на VPS уже в `.env`. В примере добавлен `GIGACHAT_MODEL` (по умолчанию `GigaChat-2-Max`). Пустые ключи не роняют API: команды по базе отвечают, свободная речь и голос говорят, что сервис не настроен.

Живой бот и HTTPS на VPS — одной командой, её же выполняет workflow:

```bash
docker compose -f docker-compose.yml -f compose.telegram-host.yml up --build -d
```
