# Invoice Keeper

Инбокс обязательств одной компании. Панель, API `/api/v1`, Telegram-бот и необязательный ассистент. Одна установка — одна организация. Живой пример той же программы: https://rekeeper.ru

Нужен Docker с Compose.

## Запуск

```bash
git clone https://github.com/ArturKolozyan/hackathon.git
cd hackathon
cp .env.example .env
docker compose up --build -d
```

Панель: http://localhost:8080  
API: http://localhost:8080/api/v1  
Swagger: http://localhost:8080/api/v1/docs

Порт берётся из `HTTP_PORT` в `.env`. По умолчанию 8080, права root и домен не нужны.

Демо, если `SEED_DEMO=true` и база пустая:

| Кто | Почта | Пароль |
|---|---|---|
| Владелец | admin@invoice.local | change-me |
| Админ отдела | maria@invoice.local | change-me-user |
| Пользователь | ivan@invoice.local | change-me-user |

Платежи кейса в отделе «Бухгалтерия»: аренда RUB, сервер USD, подписка EUR.

### Демо-кабинет для показа

Большой набор хостинг-компании: 5 отделов, 13 человек, 37 платежей, история за 8 месяцев, просрочки, сроки сегодня, через 3 и 7 дней. Запуск вручную, владелец из `.env` не трогается:

```bash
docker compose exec api python -m app.demo_data
```

Пароль демо-людей генерируется и печатается один раз, почты — `@hosting.example`. Если отделы или платежи уже есть, команда ничего не делает. `--force` стирает отделы, платежи, бюджеты, журнал и всех, кроме владельца, и сеет заново. Прошлые напоминания помечаются отправленными, воркер шлёт только сегодняшние; `--quiet` глушит и их.

## Два примера `.env`

Быстрый локальный запуск — это уже `.env.example`: `DOMAIN` пустой, `HTTP_PORT=8080`, ключи интеграций пустые.

Сервер с доменом, отличия только в значениях:

```bash
DOMAIN=rekeeper.ru
HTTP_PORT=80
HTTPS_PORT=443
ACME_EMAIL=admin@rekeeper.ru
APP_PUBLIC_URL=https://rekeeper.ru
COOKIE_SECURE=true
CORS_ORIGINS=https://rekeeper.ru
ENABLE_IPV6=true
TELEGRAM_NETWORK=ipv6
COMPOSE_PROFILES=assistant
```

Плюс свои `OWNER_EMAIL`, `OWNER_PASSWORD`, `SECRET_KEY`, токен бота, SMTP и ключ GigaChat. `SEED_DEMO=false`, если в базе уже есть люди.

## Контейнеры

```text
браузер ── HTTP/HTTPS ── caddy ── web (nginx + интерфейс)
                              └── /api/*            → api
                              └── /api/v1/assistant → assistant   (только если профиль включён)

api ── пишет в db, мигрирует, не ходит в Telegram
worker ── горизонт периодов, письма, webhook, кладёт Telegram в outbox
bot ── long polling, «Оплачено», привязки, забирает outbox, шлёт в Telegram
assistant ── GigaChat и SpeechKit, пишет в базу только через те же права, что API
db ── Postgres 16
backup ── служебный pg_dump рядом, в продукт кейса не входит
```

Никто не делает `depends_on` на `bot` и `assistant`. У каждого сервиса `restart: unless-stopped` и healthcheck.

Остановленный бот не останавливает панель, API, расписание, почту и webhook. Карточки Telegram копятся и уходят без дублей, когда бот поднимается. Каденция по умолчанию: за 7 дней и за 3 дня, в день срока без напоминания, просрочка на следующий день и дальше каждый день. За один проход — только ближайшая уже наступившая точка. Просроченное напоминание «до срока» бот не шлёт.

## Переменные

| Переменная | | Что включает |
|---|---|---|
| `POSTGRES_*`, `DATABASE_URL`, `SECRET_KEY`, `OWNER_EMAIL`, `OWNER_PASSWORD` | обязательны | база и владелец. `ADMIN_EMAIL` / `ADMIN_PASSWORD` — те же поля, если `OWNER_*` пустые |
| `TIMEZONE` | обязательна | сроки и «сегодня», пока владелец не сохранил пояс в «Организации» |
| `OWNER_OVERDUE_COPY` | нет | копия просрочки владельцу, пока не переопределено в «Организации» |
| `OWNER_RESET_PASSWORD` | нет | `true` на один запуск API записывает `OWNER_PASSWORD` текущему владельцу и пишет это в лог. Второго владельца не создаёт. После входа верните `false` |
| `DOMAIN` | нет | пусто — HTTP. Задан — сертификат Let's Encrypt |
| `HTTP_PORT`, `HTTPS_PORT` | нет | наружные порты Caddy. Локально 8080 и 8443 |
| `SEED_DEMO` | нет | демо-отделы и платежи кейса на пустой базе |
| `LOG_LEVEL` | нет | уровень логов api, worker и bot, по умолчанию `INFO` |
| `SHOW_DEMO_CREDENTIALS` | нет | блок с паролями на странице входа. В примере `true` для жюри, по умолчанию выключен |
| `ENABLE_IPV6` | нет | `false` по умолчанию. `true` включает IPv6 у сети compose |
| `TELEGRAM_BOT_TOKEN` | нет | бот. Пусто — бот жив, канал в интерфейсе «не настроен» |
| `TELEGRAM_NETWORK` | нет | `auto`, `ipv4` или `ipv6`. `auto` пробует IPv6, затем IPv4 |
| `TELEGRAM_PROXY` | нет | прокси до Bot API |
| `TELEGRAM_BOT_USERNAME` | нет | запасное имя для ссылок t.me, пока бот не сделал getMe |
| `TELEGRAM_CHAT_ID` | нет | запасной чат, только если отдел в базе один |
| `SMTP_*`, `EMAIL_ENABLED` | нет | почта. Без `SMTP_HOST` коды сброса пишутся в лог API |
| `WEBHOOK_*` | нет | webhook установки. Адрес отдела задаётся в панели |
| `GIGACHAT_AUTH_KEY` и `COMPOSE_PROFILES=assistant` | нет | контейнер и пункт «Ассистент» в панели и в боте |
| `YANDEX_SPEECHKIT_API_KEY`, `YANDEX_FOLDER_ID` | нет | голос, только вместе с ассистентом |

`COMPOSE_PROFILES` читает сам `docker compose` из `.env`. Отдельный флаг в команде запуска не нужен. Пустой профиль — контейнер `assistant` не создаётся и не крутится в рестартах.

Ключ GigaChat без профиля: в интерфейсе ассистент есть как включённый, но «временно недоступен», пока контейнер не поднят. Ставьте ключ и профиль вместе.

## Роли

Владелец один, из `.env`. Почту, пароль и имя владельца нельзя сменить из панели и из `/me`: формы скрыты, API отвечает 403. Восстановление: `OWNER_RESET_PASSWORD=true` и нужный `OWNER_PASSWORD`, перезапуск API, затем снова `false`. Второго владельца смена `OWNER_EMAIL` не создаёт. Он создаёт отделы, назначает админов, видит все платежи и единственный открывает «Организацию».

Админ отдела делает в своём отделе то, что владелец, кроме чужих отделов и учётки владельца. Пользователь видит платежи своих отделов и может отметить оплату, отменить её и поправить фактическую дату. Те же границы в API.

Человек может состоять в нескольких отделах. В шапке переключатель отделов. Добавить человека в другой отдел может только владелец.

Новый человек: владелец или админ добавляет его в «Людях» (имя, почта, роль) и копирует личную ссылку-приглашение. Письмо не уходит. По ссылке человек сам задаёт пароль, входит и видит необязательную привязку Telegram. Ссылка работает до использования или до «Новой ссылки». После входа в карточке человека — ссылка привязки Telegram и «Отвязать Telegram».

## Бот

1. В BotFather: `/newbot`, скопируйте токен в `TELEGRAM_BOT_TOKEN`.
2. `docker compose up --build -d`. Имя для ссылок бот записывает сам после getMe.
3. В панели: «Уведомления» → привязать себя и чат отдела.

Привязка Telegram одна: на привязанного пишется «Оплачено» в чате отдела, и ему же идут личные напоминания (включаются при привязке). Повторная привязка с другого аккаунта заменяет прежнюю. Кнопка «Оплачено» пишет оплату на того, кто привязан и состоит в отделе. Чужому бот присылает ссылку привязки и оплату не ставит.

## Ассистент

Код лежит в `backend/app/assistant`, процесс — контейнер `assistant`. Веб ходит в него тем же cookie/bearer через nginx. Бот ходит по HTTP с короткой сессией того же пользователя и таймаутом 10 секунд. Голос бот тоже отдаёт в `assistant`: ffmpeg есть только в его образе.

Запись в базу — только после «Подтвердить» и теми же функциями, что обычные эндпоинты (`create_payment`, `update_payment`, `confirm`). Роль проверяется ещё раз в этот момент.

`GET /api/v1/features` говорит интерфейсу, включён ли ассистент и отвечает ли он. Если процесс упал или GigaChat молчит, панель и API кейса работают, чат пишет «Ассистент временно недоступен», бот отвечает то же.

## Требование кейса → где сделано

| Требование | Где |
|---|---|
| Вход, без сессии данные закрыты | `POST /api/v1/auth/login`, `GET /auth/me`, `POST /auth/logout` |
| Список: сумма, валюта, срок, статус, дата оплаты, просрочка | инбокс и `GET /payment-occurrences` |
| Админ из `.env`, пользователи через панель | владелец из `OWNER_*` / `ADMIN_*`, `GET/POST/PATCH/DELETE /users` |
| Учётку админа из env нельзя менять в панели | `PATCH/DELETE /users/{id}` для владельца → 403 |
| Пользователь отмечает оплату и дату, границы есть в API | `PATCH /payment-occurrences/{id}`, `POST .../confirm`, `POST .../revoke` |
| Напоминание за 3 дня: название, сумма, валюта, дата, без дублей | тумблеры «За 7 дней», «За 3 дня», «За 1 день», «О просрочке» в «Организации» (по умолчанию все включены), worker + outbox |
| Оплаченный период молчит | события не создаются, если `paid_at` задан |
| Удалённый регулярный платёж не плодит новые напоминания | архив: новые периоды не создаются. Повтор уже существующей просрочки по умолчанию остаётся (`remind_archived_overdue=false` у шаблона выключает) |
| Платёж, созданный внутри окна, получает ближайшее напоминание сразу | одно событие, не пачка прошлых точек |
| Отметка и отмена — на период, история остаётся | `payment_occurrences` |
| Просрочка со следующего дня, оплата в день срока — вовремя | `app/services/schedule.py` |
| Поправка фактической даты пересчитывает просрочку и не двигает срок | `PATCH /payment-occurrences/{id}` |
| Следующий период со своим статусом, прошлые хранятся | горизонт worker |
| RUB, USD, EUR, итоги раздельно | `GET /payments/summary` |
| Часовой пояс из настроек | `TIMEZONE` |
| Нет дня в месяце — последний день | расчёт срока |
| Периодичность месяц | поле `periodicity` (месяц, квартал, полгода, год, разово, каждые N), «дата ближайшей оплаты» |
| Данные кейса | сид: Бухгалтерия (аренда, электричество, подписка) и Инфраструктура (сервер, домен, SSL) |
| Выгрузка для бухгалтера | `GET /payment-occurrences/export.csv`, те же фильтры, что у списка |
| Swagger | `GET /api/v1/docs` |

Дополнительно, сверх таблицы: календарь, итоги на дату, бюджет, журнал, чек и ссылка, почта, webhook, кнопка «Оплачено», отделы, ассистент.

Кейс не описывает отделы и говорит, что пользователь видит общий список. Здесь список ограничен отделами человека; владелец видит все. Демо: Иван в «Бухгалтерии» и «Инфраструктуре». Учётка владельца из `.env` закрыта, админов отделов ведёт владелец.

Правка шаблона меняет только будущие неоплаченные периоды со сроком от сегодня. Прошлые, просроченные и оплаченные хранят свой снимок. Фактическая сумма периода по умолчанию равна плановой; бюджет «факт» берёт её. Журнал правок пишет «было → стало». Смена фактической даты оплаты не меняет, кто оплатил.

## Примеры запросов

```bash
curl -s -c /tmp/cj -H 'Content-Type: application/json' \
  -d '{"email":"admin@invoice.local","password":"change-me"}' \
  http://localhost:8080/api/v1/auth/login

curl -s -b /tmp/cj http://localhost:8080/api/v1/auth/me
curl -s -b /tmp/cj http://localhost:8080/api/v1/recurring-payments
curl -s -b /tmp/cj http://localhost:8080/api/v1/payment-occurrences
curl -s -b /tmp/cj http://localhost:8080/api/v1/payments/summary
curl -s -b /tmp/cj http://localhost:8080/api/v1/users
curl -s -b /tmp/cj http://localhost:8080/api/v1/features
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8080/api/v1/docs
```

Создать платёж:

```bash
curl -s -b /tmp/cj -H 'Content-Type: application/json' \
  -d '{"title":"Аренда","amount":"85000.00","currency":"RUB","next_payment_date":"2026-11-05","periodicity":"monthly"}' \
  http://localhost:8080/api/v1/recurring-payments
```

Отметить период и поправить дату: `POST /api/v1/payment-occurrences/{id}/confirm` с `{"paid_at":"2026-10-23T12:00:00+03:00"}`, затем `PATCH /api/v1/payment-occurrences/{id}` с `{"paid_at":"..."}`.

## Один раз на сервере rekeeper.ru

Раньше Caddy и Telegram жили отдельными файлами. Теперь всё в этом `docker-compose.yml`.

1. Посмотреть, кто слушает 80 и 443. Если это уже сервис `caddy` из этого compose — ничего не останавливать. Останавливать процесс на хосте нужно только когда порты заняты другим Caddy или nginx, не нашим контейнером.
2. В серверном `.env` выставить `DOMAIN=rekeeper.ru`, `HTTP_PORT=80`, `HTTPS_PORT=443`, `ENABLE_IPV6=true`, `TELEGRAM_NETWORK=ipv6`. Удалить `COMPOSE_FILE`, если он указывал на `compose.telegram-host.yml`.
3. Том `caddy_data` не удалять: в нём сертификат.
4. `git pull --ff-only origin main && docker compose up --build -d`.

IPv6 у Docker bridge на части VPS не выходит в интернет, даже если у хоста он есть. `ENABLE_IPV6=true` просит compose включить IPv6 у сети. Если Telegram всё ещё недоступен из контейнера, `TELEGRAM_PROXY` на прокси хоста или проверка `ip6tables`. Отдельного host-network файла больше нет: без IPv6 на машине оставьте `ENABLE_IPV6=false`, бот уйдёт в IPv4 через `TELEGRAM_NETWORK=auto`.
