# Invoice Keeper

Инбокс регулярных обязательств команды: сверху просрочено, потом скоро, потом остальное. Период — это карточка («Сервер · ноябрь · $40 · до 12.11»), шаблон — только правило. «Оплачено» подтверждает человек, не банк.

Telegram — второй экран того же инбокса — в этом куске ещё не ходит в Bot API. `worker` уже догоняет периоды и зовёт общий пайплайн напоминаний: почта и webhook, если они включены. Хук бота — `app.integrations.telegram.deliver`.

## Запуск

```bash
cp .env.example .env
docker compose up --build
```

Windows:

```powershell
copy .env.example .env
docker compose up --build
```

- Приложение: http://localhost:8080
- Swagger: http://localhost:8080/api/v1/docs
- API напрямую: http://localhost:8000/api/v1/docs
- OpenAPI в репозитории: [openapi/openapi.json](openapi/openapi.json)

Данные Postgres лежат в томе `pgdata` и переживают `docker compose restart`. Демо-шаблоны создаются один раз; пароль админа при старте API синхронизируется с `ADMIN_PASSWORD`.

### Демо-вход

Пароли из `.env`, они же на экране входа.

| Кто | Почта | Пароль |
|-----|--------|--------|
| Админ | `admin@invoice.local` | `change-me` |
| Иван | `ivan@invoice.local` | `change-me-user` |
| Мария | `maria@invoice.local` | тот же, что у Ивана |

В инбоксе уже есть аренда (RUB), сервер (USD) и подписка (EUR): просроченные, ближайший и будущие периоды, плюс история, в том числе одна оплата с опозданием.

Участник видит очередь и может закрыть период. Шаблоны и люди — только админ. Проверка прав на API, не только в меню.

## Что в compose

| Сервис | Роль |
|--------|------|
| `db` | PostgreSQL 16, том `pgdata` |
| `api` | FastAPI, миграции Alembic, сид, `/api/v1` |
| `worker` | Горизонт периодов. Telegram сюда, не в API |
| `web` | Собранный React за nginx, `/api` проксируется на `api` |

Локально без Docker: поднять Postgres, `pip install -r backend/requirements.txt`, из `backend/` выполнить `alembic upgrade head` и `python -m app.entrypoint serve`, фронт — `npm install && npm run dev` в `frontend/` (прокси `/api` на порт 8000).

Тесты:

```bash
docker compose exec api python -m pytest -q
```

## Допущения этого куска

Бриф AEZA с точными полями в репозиторий не положен, поэтому контракт зафиксирован в OpenAPI.

- «Скоро» = срок через `SOON_DAYS` дней или раньше (по умолчанию 3, как порог напоминания в [docs/product.md](docs/product.md)). В день срока это ещё не просрочка: оплата в этот календарный день — вовремя.
- Дата считается в `TIMEZONE` (Москва). Если в месяце нет такого числа — последний день.
- Просрочка не отменяет следующий месяц: воркер и чтение инбокса достраивают периоды на `HORIZON_MONTHS` вперёд.
- Неоплаченный период подхватывает сумму, валюту, день и название шаблона. Оплаченный — снимок.
- Удаление шаблона в API — архив: новые периоды не рождаются, старые строки остаются.
- Закрыть период и поправить фактическую дату может любой активный пользователь. Создание шаблонов и управление людьми — только `admin`.
- Итоги (`GET /api/v1/payments/summary`) — суммы по валютам, без курса. `?as_of=YYYY-MM-DD` считает их на конец этого дня в `TIMEZONE`: оплата позже даты ещё открыта, просрочка по тому же правилу. Без параметра — как сейчас.
- Календарь (`GET /api/v1/payments/calendar?year=&month=`) — периоды месяца по дате срока. В панели клик открывает карточку.
- Чек периода: `receipt_url` (https) и `receipt_note`. Меняются через PATCH, в том числе отдельно от оплаты.
- Бюджет: админ задаёт план на месяц (`2026-10`) или год (`2026`) по каждой валюте. Факт — сумма закрытых периодов этого месяца или года, «ожидается» — ещё открытые. Отчёт видят все.
- Журнал (`GET /api/v1/audit-logs`) — только админ. Вход, выход, шаблоны, люди, оплаты, бюджет, чек. Пароли и токены в журнал не пишутся.
- Напоминание решает один сервис `should_remind`: не оплачен, шаблон не в архиве, до срока ≤ `SOON_DAYS` (просрочка тоже). Каналы это правило не копируют.
- Почта: `EMAIL_ENABLED=true` и заполненные `SMTP_HOST`, `SMTP_FROM`, `SMTP_TO`. Иначе воркер молча пропускает письмо.
- Webhook: `WEBHOOK_ENABLED=true` и `WEBHOOK_URL`. События `occurrence.reminder`, `occurrence.paid`, `occurrence.unpaid`. До `WEBHOOK_ATTEMPTS` попыток. Секрет даёт заголовок `X-Rekeeper-Signature: sha256=<hmac тела>`.
- Успешная отправка помнится отдельно по каналу. Неподключённый Telegram не считается отправленным.
- Сессия: opaque-токен в httpOnly-куке и в теле логина (`Authorization: Bearer`). Logout отзывает её на сервере.

## Не в этом куске

Живой Telegram-бот и кнопка «Оплачено» в чате. С московского VPS к `api.telegram.org` по IPv4 таймаут, по IPv6 ответ есть — клиент бота должен жить в `worker` и ходить по IPv6 (`TELEGRAM_FORCE_IPV6`).

Чтобы подключить бота, реализуйте `deliver(text, *, chat_id, occurrence_id, event)` в `backend/app/integrations/telegram.py`. Не заводите второй отбор «кому пора напомнить» — его уже делает воркер. `NotImplementedError` значит «пропустить», сеть — «повторить на следующем тике». Чат: `TELEGRAM_CHAT_ID`, токен: `TELEGRAM_BOT_TOKEN`.
